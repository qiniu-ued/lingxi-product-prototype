# Repository guidance

## Product and ownership

- This is a Mac-local collaborative workbench: an Electron parent owns one Node 24 service and the canonical product WebContentsView; operator and display share task state. The standalone browser service retains draft-only behavior. Voice, pointer and keyboard must use the same command path.
- Read `docs/product-design.md` and `docs/architecture.md` before changing product or system boundaries. Record architectural changes in `docs/adr/`.
- Preserve designer-owned `source/` and root `dist/` unless the task explicitly changes the interaction prototype. Exclude both from project-wide formatting. `docs/reference/` is historical, not the current specification.
- Report real execution events. Saved drafts, timers and demos must never appear as completed Agent work. Persistent Codex threads, terminal, diffs, scoped preview MCP, and Lingxi OTA/WSS/PCM adapters are implemented. Local Chinese wake detection uses sherpa-onnx in a private worker; default-keyword accuracy and Mac native loading remain subject to hardware validation. Real provider binding/audio remains unverified until hardware evidence is recorded. Protocol fixtures are not proof of real model, audio or AirPlay success.

## Repository map

- `apps/desktop/`: Electron lifecycle, trusted preload and canonical preview. Bundle Node/npm; keep SQLite in the separate Node process. Generated pages must have no preload/Node/IPC or local-service network access. Only fixed, schema-validated native actions and versioned preview operations are allowed.
- `apps/web/`: React operator `/` and passive `/display`; no direct shell, Codex or AirPlay access.
- `apps/server/`: Fastify, SQLite, SSE and Codex App Server tasks; Lingxi protocol integration is implemented; real provider verification remains pending. Keep loopback binding and Host/Origin validation. Lingxi bindings use only official OTA/WSS endpoints; credentials pass private IPC to safeStorage, never HTTP responses/logs. Never download OTA firmware.
- `packages/protocol/`: shared Zod schemas, types and adapter contracts. Validate HTTP input and external-provider events at boundaries.
- `scripts/`: production smoke checks and architecture-specific runtime packaging.
- `/setup` inspects Codex, Lingxi, wake assets/native library and microphone status in parallel, then offers three steps based on results. Desktop operator startup runs the same read-only check before mounting drafts/tasks; missing/failed configuration opens the wizard. Passive display and browser foundation bypass this startup gate. Explicit continue applies only to the current page; refresh/restart checks again. Do not add periodic redirects that lose working drafts or interrupt tasks. See ADR 0010. Keep diagnostics read-only: no installation, login, thread creation, turns or credential-file reads. Separate explicit-click actions may install the stable latest Codex into managed storage or start official browser login. Keep fixed operations, strict local Origin validation, retry IDs, cancellation and child cleanup; never accept arbitrary executable input from HTTP. Diagnostics never start tasks or audio; the separate operator startup controller may start default local wake under ADR 0013. Task capability comes from the private desktop bridge, not a successful diagnostic. Microphone diagnostics query status without requesting permission or media streams; a not-yet-requested permission is informational. Wake diagnostics load only the native module in a bounded, owned Worker, without keyword files, inference or audio. Lingxi inspection reads only encrypted local configuration; it never registers a device, connects WSS or opens the microphone. OTA registration and activation remain explicit; a separate startup controller may connect an existing binding under ADR 0013; an authorized wake stages fresh capture only when the service is ready.
- `docs/development.md`, `docs/deployment.md`, `docs/testing.md`: authoritative run, delivery and verification instructions; update them when commands or behavior change.
- Keep the operator's Settings entry permanently visible. `/settings` reuses the wizard's actual configuration forms, with Codex, Lingxi/voice execution and wake/microphone categories; passing inspection never closes it. In-page navigation retains the mounted workspace and its per-conversation drafts, but unmounts the audio owner to stop capture/wake/playback. Returning may restore default local wake only when the persisted choice permits it and microphone authorization is already granted; it must not resume a cloud capture. Direct URL reloads still lose page-memory drafts. Passive display must not show configuration controls. See ADR 0011.

## Development

- Use Node 24.x and npm 11.x (`.nvmrc`, `packageManager`). Install with `npm ci`; commit dependency changes together with `package-lock.json`.
- Desktop development: `npm run desktop:dev`; quit and restart to load compiled changes. Build Mac distributions on each target architecture with `npm run desktop:pack`.
- Browser foundation: `npm run dev`; the operator is at `http://127.0.0.1:5173/` and display at `/display`. Production uses `npm run build` then `npm start` on port 4310.
- Preserve command IDs across retries, reject stale artifact selections, and keep display connection status separate from durable task state. Do not drop user input on request failure.
- Task request IDs are durable in `workspace_turns_v2` (legacy receipts originate in `workbench_requests`); never replay interrupted tasks automatically. Preserve project-specific browser storage, reject stale binding/ref selections, and do not refresh an unchanged artifact after a browser-only action. Keep full durable conversation/turn history and multiple pending question requests. Persistent task connections are separate from read-only diagnostics. Buffer notifications until turn/start returns its actual turn ID; drain only matching events. Wait for static publishing before dispatching the next queued turn. Failure/interruption pauses queued inputs; uncertain steer delivery is durably reserved and never resent. Terminal replay is ephemeral unless the user explicitly adds it to a conversation. Desktop terminal stdin intentionally belongs to the user; only app-selected shell argv may reach command/exec, never expose executable/argv parameters or terminal access through device/preview MCP. Sidechat disables all discovered MCP servers and their plugin IDs per turn, and uses read-only/never; fail closed on discovery failure. A conversation Fork shares files until isolated worktrees are implemented.
- Live preview URLs require explicit loopback binding, exact project origin and matching WebSocket only; reject the workbench service port and keep generated pages without Node/preload/IPC. Static freeze rules remain. Validate target bindings on every submission and do not claim HMR revisions are immutable source snapshots.
- Voice uses PCM16LE/16kHz/mono/20ms over private IPC only after manual capture or the persisted default-wake policy and existing OS microphone authorization permit local wake. Idle wake frames stay local; only a wake-triggered, freshly staged capture may upload. Refuse incompatible negotiation, do not reinterpret Opus as PCM. STT alone cannot execute. Before capture, stage mouse targets, attachments and the keyboard draft once for the exact project/conversation; reject stale/retargeted staging. Optional device MCP submission is capture/context-bound and reuses the same durable task ID. Stop speech and stop tasks are distinct. Do not store audio, expose secrets or request OS permission on the automatic path. Respect persisted explicit off. Fresh app startup may restore authorized local wake; faults and suspend pause the current runtime, and cloud capture never resumes automatically. Keep the local microphone lease, playback suppression and bounded Worker queue; never treat fixture traffic as real provider success.
- Voice handoff diagnostics are ephemeral: tool-list discovery proves only that the list was requested; only a real Workbench.start receipt permits a submitted task ID. Cloud TTS/STT alone never indicates a Codex task. Preserve an accepted receipt when later tools fail, reset it for the next capture, and ignore stale-context transcripts. Show allowVoiceSubmit and specific sanitized failure reasons on both screens. Consent stays off by default and separate from wake. Cloud agents require intent recognition plus a tool-capable model; role text/MCP instructions are hints, not evidence of cloud configuration or model compliance. Keep one shared role text and link official guidance from settings. The fixed wake-keyword command changes only the current service run, with detection off; it must not connect, install or open audio. No persisted config/Task schema change is needed for these diagnostics.
- Changes to persisted data require an explicit schema/migration and compatibility decision. An application downgrade does not imply a database downgrade. workspace_state_v2/workspace_turns_v2 import v1 only once and leave legacy tables intact; later v1 writes are not re-imported. Voice identity persists separately from OS-encrypted credentials. See ADR 0004.
- Model controls belong in the composer. Fetch actual paginated model/list data without starting a thread/turn; show only supported reasoning choices and preserve preferences on failure. Settings affect newly submitted turns; queued/running turns retain their captured settings.
- The warm desktop layout keeps project creation/open/refresh in the header split button, with persistent Settings and Workspace entries; conversations, terminal, Diff, catalogs and context details stay under Workspace; model/effort/mode/permissions are inside the collapsed keyboard composer. Known turn usage appears as one muted English line; missing reports are hidden and unknown cache percentages omitted. Context occupancy is a progress bar on operator and passive display, with a hover/focus tooltip and shared click/voice-expanded details. Whole-turn quote/Sidechat actions are removed; Fork and copy are accessible icon buttons. Selecting text within one history message exposes quote/Sidechat actions. Keep these controls reachable, open and focus the composer for quotes, pointer selections, attachments and accepted voice drafts, and keep approval/question panels visible outside collapsed details. The footer is the microphone/voice surface; label manual capture as such. Passive display voice polling must never start capture. Validate operator/display single-screen fit and native preview bounds when moving panels; update usage docs when entry points change.
- History quotes must match a canonical task/message in the selected project/conversation. Validate quote-bearing forks before and after async connection acquisition. Selected Sidechat forks inherit history through the finished source turn and stage a quote only; they never submit a model task automatically. Keep composer drafts keyed by project/conversation, preserve the original target across async callbacks, and carry Sidechat results into the parent draft after switching. Drafts are page-memory only; request-only quote metadata must not change strict persisted Task/v2 formats. See ADR 0008. Undo/file checkpoints remain unimplemented; do not imply stopping or forking restores files.
- Use official experimental collaborationMode (plan/default) with developer_instructions:null for built-in instructions; never prepend a pretend Plan prompt. Discover modes and managed requirements read-only. Before turn/start, await matching thread/settings/updated confirmation for mode, model/effort, approval policy/reviewer and every requested sandbox field; unsupported or unconfirmed settings must not start a model task. Permission choices map Manual to workspaceWrite/on-request/user, Approve for me to workspaceWrite/on-request/auto_review, and Full Access to dangerFullAccess/never/user. Sidechat always overrides to readOnly/never/user and disables MCP. Never auto-accept requests in app code to simulate auto-review. Persist preferences and captured per-task permissions in workspace_permissions_v1, outside strict v2 snapshots/Task JSON. See ADR 0007.
- Skills/MCP/limits are validated, projected readable catalogs, not raw JSON. Preserve per-category failures, read all bounded MCP pages, omit provider config/tokens/raw errors, and never infer quota availability from percentages. Only explicit verification may create isolated ephemeral threads; the verification client must be closed on completion and app shutdown, and must not request turn/start or alter the selected project/thread. Distinguish generated schema/fixture evidence from real CLI/model evidence.
- Voice mode switching is an allowlisted workbench_set_mode device MCP action, uses the shared workspace command with capture/context guards, and requires the existing explicit voice-control consent. STT alone cannot change modes; speech cannot elevate permissions. Settings affect new submissions, at most one distinct mode per capture, never an already-submitted task.
- Context occupancy uses tokenUsage.last.totalTokens / modelContextWindow, never cumulative total. Unknown reports/capacity stay unknown. Handle early and post-completion notifications; reject stale turn/thread data and allow reported usage to fall after compaction. Confirmed thread configuration is not per-turn execution telemetry. Keep workspace_thread_runtime_v1 metadata out of strict v2 snapshots for downgrade compatibility (ADR 0005).
- Completed-turn consumption uses cumulative total deltas across the whole turn, never the last model request or a sum of duplicate snapshots. Cache hit rate is the turn's cachedInputTokens / inputTokens; unknown cache counts and zero input have no percentage. Persist raw baselines/reports separately in workspace_turn_usage_v1, strip turnUsage from v2 snapshots, and match task/conversation/Codex thread/turn IDs. Known historical late reports may correct their own turn and the next baseline, but must not replace newer context occupancy. Missing baselines and counter resets remain unavailable; failed/interrupted summaries are reported consumption only. See ADR 0006.
- Wake model downloads must use the pinned release URL, size/time bounds, SHA-256 and fixed archive members. Keep native inference in its Worker; no provider credentials or generated-page access. Default local wake and explicit voice task control remain separate permissions; local wake defaults on only for fresh installations and authorized microphones (ADR 0013). See ADR 0009. Context-detail voice controls share the existing capture/context/consent guards and never start a model turn.
- Multi-engine support remains a proposal in `docs/multi-engine-options.md`. Only Codex executes today; do not expose fake engine choices or map Codex auto-review/read-only guarantees onto another provider without capability verification. Future setup checks target the selected engine, not every installed alternative.
- Keep implementations small. Test observable behavior and state boundaries; avoid tests that simply repeat the implementation.

## Required verification

- Run `npm run check` for implementation changes: Biome, TypeScript, unit/API coverage, production build, and real-process startup/restart smoke checks.
- Also run `npm run test:e2e` when browser behavior, SSE, command APIs or synchronization changes. Install Chromium with `npx playwright install chromium` first. CI installs browser dependencies.
- Run `npm run test:desktop` for desktop, task or preview changes: it uses a real Electron page, private Node child and a deterministic App Server peer, without provider credentials. Keep native lifecycle/preview checks in this integration harness; protocol/server logic remains subject to unit coverage gates.
- Run `npm run release:pack` for packaging/launcher changes; on Mac also run `npm run desktop:pack` to verify the extracted `.app` with its bundled Node. It installs production dependencies into a clean staging directory, then extracts and boots the actual archive. It packages the host architecture; do not relabel Linux output as a Mac build.
- Validate workflow edits with actionlint 1.7.12: `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.12`. Run `npm run audit:production` for dependency/release changes; resolve reported high/critical production issues without blindly applying `npm audit fix --force`.
- Coverage gates live in `vitest.config.ts`: 85% statements/lines/functions, 75% branches. The process entry point is verified by production smoke checks. Do not lower thresholds or exclude business logic just to pass CI.
- Keep real-device evidence distinct: CI does not verify Mac microphone access, provider login, meeting-room audio or AirPlay. State precisely which checks ran and which remain unverified.

## Delivery and data

- CI uploads Apple Silicon and Intel runtime archives plus desktop app ZIPs and checksums after their checks. Delivery currently means downloadable artifacts; no automatic install, cloud deployment, Developer ID signing, notarization or auto-update exists.
- Respect the user's requested Git workflow. Keep changes on the working branch; do not merge or publish a release as a side effect of fixing checks.
- The user has authorized merging completed work when GitHub Actions is blocked by exhausted quota. Run the applicable local checks, report CI/platform/package verification gaps, and merge without waiting for quota recovery. This exception does not justify ignoring actual code/test failures or lowering checks; leave workflows and coverage gates intact.
- Never commit credentials, local databases, recordings, package output, dependency directories or test reports. Root `dist/` is the intentional designer-prototype exception.
- Runtime data belongs outside versioned install folders. Stop the service before a file-copy backup; account for SQLite WAL files. Do not delete or migrate user data as routine cleanup.

- Product UI brand is 丽塔同学; retain technical Lingxi identifiers, user-data paths and official provider URLs. Startup opens the passive display even without a project; this never automates AirPlay or grants screen/audio permissions. The preview toolbar exposes 批注修改; keep annotation text per draft, include it with the validated selected element on direct submission, and allow cancellation.
- Explicit voice sessions survive silence and TTS. Idle PCM stays local, bounded speech-prefix buffers exist only after user enablement, and each detected utterance must stage fresh context before upload. Segmentation/response deadlines never imply closing the conversation or replaying tasks. The four-second lease detects missing audio frames, not quiet samples. Disconnect, loss of audio, settings, suspend and explicit stop release capture; reconnect never restores a cloud capture. Settings return can restart authorized default local wake; explicit stop persists off. `workbench_voice_close` needs a current context-bound capture but no task-execution consent and cannot stop Codex or raise permissions. Keep model/provider-dependent voice close separate from the always available manual stop. See ADR 0012.

- ADR 0013 supersedes earlier manual-only wake defaults: persist independent wake and service intent in wake-preferences.v1.json and voice-connection-preferences.v1.json, separately from tokens/Task/v2. Startup connects an existing binding without uploading idle wake audio. Maintain ping/pong and at most six bounded backoff retries; authentication/protocol failures stop retries. Manual service disconnect persists off and keeps idle local wake; global voice close persists both off. Never let wake/online/resume override an explicit off or replay a capture. Fresh defaults on; existing database without a recorded choice uses legacy-review/off once, never interpret allowVoiceSubmit as wake consent. Corrupt/unwritable intent disables auto. Start the local model before opening automatic media, use fixed native microphone-status without a prompt, and keep idle detection independent of WSS. No automatic download/binding. TTS/input requests and actual getSettings values are different; verify source, suppress known playback plus a bounded tail, and never claim other players or virtual inputs are fully filtered. See docs/audio-input-and-echo.md.

- Shutdown is terminal and idempotent: stop new native work/reconnection before cleanup. Every Node IPC send must own a callback as well as check connection state; the check alone cannot prevent channel-close races. The desktop bridge rejects and clears pending work after disconnect/close. Keep unexpected runtime transport errors visible; do not add global uncaught-exception suppression. Await wake Worker termination, bound owned child shutdown, and test parent disconnect/startup cancellation with `scripts/test-shutdown.mjs` plus real Electron exit assertions.

- Annotation hover is a read-only, schema-validated hit test in the canonical isolated world, with the outline drawn over the operator screenshot. Account for screenshot letterboxing, resize and zoom; drop stale async hover/click replies after cancellation or binding changes. Click selects context without invoking the page. Support axis-aligned same-origin iframe descendants; opaque/cross-origin or transformed iframe contents fall back to the frame element. Keep generated pages without IPC/preload and preserve the strict persisted PreviewSelection shape.

- Voice chat and diagnostics are separate in-memory stores: chat is bounded to 24 turns/8 messages per turn/64k characters and never auto-persisted; diagnostic metadata is capped at 128 events/30 minutes and has no content or device identity fields. Copy exports only schema-validated metadata, build identity and UTC/timezone; clipboard failures offer manual text and must not claim success. Preserve status-call evidence and actual task receipts independently of tools/list. Chat can run without a project; task submission still requires one. Pin scope, ignore stale socket/stream fragments, keep final messages final, retain within-service refresh/reconnect and clear on service exit. Do not add cross-restart body persistence without explicit retention/deletion authorization. See docs/voice-diagnostics.md.
- Detailed voice debugging is a separate, explicit opt-in store, off on every service start: at most 64 events/10 minutes/8192 payload characters per event, bounded depth/fields/strings, metadata IDs plus credential-redacted inbound/outbound text protocol and local events. Never record binary audio, arbitrary environment variables or entire configuration. Redact known binding secrets/identity, nested credential keys, encoded JSON and credential-bearing strings before truncation. Keep summary copies free of detailed bodies even while detail is enabled; provide a warning, preview and separate copy/fallback. Disable clears content immediately; closing the panel does not disable recording. Do not enable it on a user's device without their action. Record disconnect source/reason/close code/retry attempts without raw reason strings in summaries; clear capture/draft/subtitle on transport disconnect while preserving accepted-task correlation. Network recovery never resumes old capture or overrides explicit off. A close event alone does not identify a remote idle policy or physical network fault.
