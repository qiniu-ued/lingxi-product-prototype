# 丽塔同学共创工作台

[![CI](https://github.com/qiniu-ued/lingxi-product-prototype/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/qiniu-ued/lingxi-product-prototype/actions/workflows/ci.yml)
[![Codecov](https://codecov.io/gh/qiniu-ued/lingxi-product-prototype/branch/main/graph/badge.svg)](https://app.codecov.io/gh/qiniu-ued/lingxi-product-prototype)

在沙发或会议室里提出想法，让 Codex 制作产品，大家在大屏上看进展、体验作品，再继续修改。目标支持七牛语音语音、鼠标点选和键盘输入。

当前分支提供 **Mac 桌面工作区、常驻 Codex 会话、交互终端、Diff、对话历史、Sidechat/Fork 与丽塔同学设备绑定向导**。采用 Electron + React + TypeScript + Node.js 24。丽塔同学 PCM 收音、转写、播报和设备 MCP 已实现协议适配，真实账号与 M1 Pro 音频尚待验收；本地中文唤醒词已接入，远场效果与 Mac 原生库待真机验收；AirPlay 自动配对未实现。设计师的原始演示保留在 `source/` 和根 `dist/`，其中语音和投屏仍是预设剧情。

## 在 Mac 使用

从 [Actions → CI](https://github.com/qiniu-ued/lingxi-product-prototype/actions/workflows/ci.yml) 对应 PR/提交的全部通过运行下载 `runtime-macos-15-<commit>`（Apple Silicon）或 `runtime-macos-15-intel-<commit>`。解开 artifact，再解开其中的 `Lingxi-0.1.0-darwin-arm64.zip` / `darwin-x64.zip`，将 `Lingxi.app` 拖到「应用程序」并打开。**桌面包内置 Node、npm 和本机服务，日常启动与退出不需要终端。**

当前是未签名、未公证的开发预览包，macOS 可能阻止首次打开；可信来源包的放行方式及校验见[部署文档](docs/deployment.md)。若组织策略禁止未签名应用，需等待签名版本。不要关闭全局 Gatekeeper。

若 Actions 因额度耗尽无法运行，新提交不会自动生成 Mac 安装包。已安装的旧包不会自动更新；要体验最新代码，可在 Mac 按下方源码步骤运行 `npm run desktop:dev`，或使用 `npm run desktop:pack` 本机构建。
1. 启动时自动检查 Codex、丽塔同学、唤醒模型与麦克风权限，缺项或检查失败会打开连接向导；检查通过直接进入工作台。日后从右上角常驻「设置」管理连接，检查全部通过也不会关闭设置页。按需一键安装 stable latest Codex CLI，并在官方浏览器登录。仅有 Codex 桌面应用时仍需要 CLI。
2. 向导中获取丽塔同学六位绑定码，在官方控制台登录、创建智能体并绑定设备，点击「我已绑定，检查连接配置」。向导自动保存加密凭证；连接后测试收音与播报，无需编译音频客户端。
3. 在第三步「配置唤醒模型」下载约 33 MB 模型，并复查原生库与麦克风权限。检查不自动开麦、登录或连接语音；也可「暂时用文字进入工作台」，刷新/重启后会重新检查。
4. 在「工作区」新建或打开一个允许 Codex 修改的项目文件夹，展开底栏「文字输入」，输入本轮要求并提交。额外权限和问题在对话区处理；执行时可在文字输入面板停止任务，也可使用已授权的语音停止。
5. 简单作品使用 `preview/index.html`，完成后自动发布。已有 React/Vite 等项目可通过「工作区 → 终端」运行开发服务器，再切回预览，在「工作区」展开「连接项目开发服务器」填写其 loopback 地址，例如 `http://127.0.0.1:5174/`。
6. 大屏窗口持有唯一的作品页面，电脑端显示它的实时截图。通过预览旁「批注修改」移动鼠标查看元素高亮和尺寸，点击锁定后填写专属批注或本轮指令；Esc 取消，批注模式下滚轮浏览页面。文字输入面板会自动展开；需要体验按钮和表单，可直接操作大屏窗口，也可要求 Codex 点击、输入或滚动。
7. AirPlay 暂由 macOS 控制中心连接。应用启动默认打开大屏窗口，无项目时展示空状态；应用优先使用已有外接屏，关闭大屏后可从「工作区 → 打开大屏」重新打开；需要时自行移动窗口。连接电视和系统 PIN 由 macOS 管理。
8. 关闭操作台窗口，或菜单「退出丽塔同学」，会停止应用启动的服务与任务。关闭大屏窗口只隐藏大屏，不取消任务。退出会停止新工作、清理语音/唤醒并等待本机子进程结束；无需额外配置。文件修改不会因停止任务而回退。

真实提供方登录、模型调用、M1 Pro 麦克风和电视仍需要本机验收；协议替身测试不算这些能力已验证。你可以在本机登录并绑定丽塔同学设备，无需向开发者发送密码或密钥。在「设置 → 语音唤醒与麦克风」下载模型、修改本次运行的唤醒词与检查权限，已有麦克风授权和模型后，回工作台自动监听“丽塔同学”；说“丽塔同学”，听到提示音后再说指令。唤醒前音频留在本机，不保存录音；关闭选择会保存；重新启动按偏好恢复本地唤醒，音频故障或休眠暂停当前检测，服务断网会有界退避重连，不恢复旧的云端收音。

**能语音聊天不代表已经交给 Codex。** 默认仅形成转写草稿；如需直接说“把这个页面变成粉色”就执行，请在「设置 → 丽塔同学与语音执行」勾选允许语音提交，并重新连接。七牛云端智能体须启用「统一意图识别」并使用支持工具调用的模型；「无意图识别」只做聊天。设置页提供可复制的工作台角色说明和[官方配置文档](https://linx.qiniu.com/docs/xrobot/guide/agent-config)。语音交接状态显示工具是否被读取、具体阻止原因，以及真实接收后的任务编号；没有任务编号不能视作 Codex 已开始。语音提交携带收音开始时的鼠标标记、附件和键盘草稿，普通 STT 不自动执行。

## 电脑端工作区

默认界面以暖色双栏显示作品与对话，底栏显示麦克风状态和语音操作。辅助功能集中在右上角「工作区」、底栏「文字输入」及每轮回复后的「⋯」（本轮详情）；这些入口默认折叠，提交成功后收起文字输入。
- 右上角常驻「设置」集中管理 Codex 安装/登录、丽塔同学绑定与语音执行许可、唤醒模型/关键词/麦克风。设置页可重新检查全部配置或打开连接向导；返回工作台保留本页未发送文字和附件，录音与唤醒检测会停止，返回后按已保存偏好和现有授权恢复本地唤醒，不自动恢复云端收音。刷新/退出仍不保留草稿。
- 对话可新建、搜索标题、重命名、归档和切换，保留每轮消息与实际执行记录。执行中可排队或补充当前任务，提问显示选项并允许填写答案。
- 「终端」提供项目 PTY；选中输出可添加到对话。停止任务和结束终端分开，退出应用结束所有自有连接与终端。
- 「Diff」区分 Codex 本轮 patch、Git 已暂存和未暂存变更；选中行并填写评论，可加入下一条指令。
- 预览旁「批注修改」可选择元素并填写批注，直接提交会连同元素引用发送；也可保存多个版本化元素标记，再统一说明修改。上下文附件明确提交后才发给 Codex。
- 用鼠标选中单条历史消息中的一段文字，点击浮动工具栏的「引用到对话」，再撰写回复；只引用选段，保留已写草稿，不自动提交。支持自己的消息和 Codex 回复，每次最多 16,000 字符。
- 选段后点击「选段 Sidechat」，从该已结束轮次创建只读讨论，并将选段放入新讨论的草稿；填写问题后再提交。它继承截至该轮的对话上下文，与主任务串行。主对话与 Sidechat 的文字、附件草稿分别保留在当前页面内，刷新或退出后不保留；结论可带回原对话。
- 每轮回复后仅用图标提供 Fork 与复制；引用/Sidechat 只保留选段入口，讨论中的选段可「引用到原对话」。Fork 共享项目文件，尚未提供独立 Git worktree。当前没有「撤销上一轮」：停止、Sidechat 和 Fork 都不会回退文件。
- 展开「文字输入」后，可在输入框上方选择模型与 Reasoning Effort，切换模型时调整为兼容强度。新选择用于后续提交，正在执行和已入队的轮次保留原选择。
- 对话底部默认只显示上下文进度条，hover 显示 `Context Window: xx/xx used.`，点击展开详细分类与累计用量；操作台和大屏共享展开状态。未知容量/用量不显示假百分比。
- 每轮有报告时在回复下方显示一行灰色小字，例如 `32,000 Token used, 30,000 Input, 2,000 Output, 40.0% Cache hit.`；没有报告则隐藏，缓存无法计算时省略该项。多次请求累计、迟到修正和持久化逻辑不变。
- 在「文字输入」的「工作模式」中选择执行／计划模式，使用官方 collaboration mode 协议。权限可选 Manual、Approve for me、Full Access；选项受 CLI 和组织策略约束，提交前等待 Codex 确认，新选择不改变已排队任务。Sidechat 始终只读。
- 在「文字输入 → 模式说明与兼容验证」点击「验证执行设置」，在独立临时会话验证模式和权限接口，不请求模型执行或修改项目。当前云环境的真实 CLI 启动仍受只读配置目录限制；正式接口接入已通过协议替身，真实 Mac 需要点击该按钮验收。
- 「工作区 → 工具与额度」按需展示 Skills 名称、说明与启用状态，MCP 连接、授权和工具列表，以及额度窗口、使用进度与重置时间；各部分可独立报告不可用。完整功能对照见 [工作区能力表](docs/workspace-capabilities.md)。
- 连接丽塔同学并开启语音控制后，可说“切换到计划模式”或“切换到执行模式”。由设备 MCP 调用同一模式命令，普通转写仍是草稿；也可说“打开上下文详情”或“收起上下文详情”，同时作用于电脑和大屏。权限级别只通过操作台选择。

## 从源码开发

需要 Node.js **24.x**、npm **11.x**：

```sh
npm ci
npm run desktop:dev
```

`desktop:dev` 编译后启动桌面应用；修改源码后退出并重新运行。纯浏览器基础模式使用 `npm run dev`，操作台 <http://127.0.0.1:5173/>、大屏 `/display`、向导 `/setup`、设置 `/settings`，保留建议保存和同步功能。独立浏览器服务没有桌面预览控制，也不会执行 Codex 任务。

```sh
npm run check
npm run test:e2e
npm run test:desktop
npm run audit:production
# 在目标架构的 Mac 构建桌面 ZIP 与兼容的终端运行包
npm run desktop:pack
```

主动点击「开始收音」或唤醒后会持续保持语音会话：静音只结束单句话，播报后继续在本机等你说话；待说话音频不上传。每句话重新暂存当前项目、点选和草稿，一次最多一个任务。点击「关闭语音」或明确说“关闭语音”结束会话；语音关闭无需开启任务执行许可，但仍须云端调用对应设备工具。音频中断、设置切换、休眠与退出会停止当前采集；网络断开后自动重连服务，不恢复旧收音或重放任务。默认开大屏只打开应用窗口，不自动连接 AirPlay。

应用启动即自动连接已有绑定的语音服务，同时在模型和现有麦克风授权满足时本地监听“丽塔同学”。待唤醒音频不上传；服务使用保活及最多六次退避重连，并显示连接状态。旧安装没有长期选择记录时，分别在「设置 → 丽塔同学与语音执行」确认自动连接、在「语音唤醒与麦克风」确认自动唤醒，之后记住选择。缺模型或首次/拒绝麦克风授权时显示配置入口，不自动下载或弹授权。点击或说“关闭语音”会停止输入、断开服务并保存两项关闭选择，重启也不重开；也可分别关闭唤醒或断开服务。详见 [默认唤醒 ADR](docs/adr/0013-default-local-wake.md)。

应用使用系统默认音频输入，没有直接采集系统输出或保存本地录音文件的内置路径。默认输入为虚拟回环设备，或外放进入物理麦克风，都可能收到电脑声音；不能据此确认某次反馈的根因。应用自身播报增加尾音抑制，并提供实际输入与处理状态；[音频审计和 Mac 对照步骤](docs/audio-input-and-echo.md)。
