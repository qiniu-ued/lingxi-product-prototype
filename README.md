# 灵矽 · 主动唤醒与语音创作原型

这是用于产品评审的 39 步交互流程原型，展示无屏控制端、AirPlay 连接、语音创作、Agent 状态、方案讨论与投票、选定后生成攻略、修改、断线及重连。

## 文件

- `source/lingxi-voice-prototype.html`：可编辑的交互原型片段。
- `dist/index.html`：可直接托管的独立网页，包含样式、交互及独立运行包装。

## 使用

打开网页后，点击「自动演示」播放流程，或用「上一步」「下一步」逐步评审。演示控件位于产品画面之外；所描绘产品由总发言人主动唤醒后，通过语音提交需求。每次指令都可见「待唤醒 → 收音中 → 已提交并关闭麦克风 → 开始处理」；转写在收音时暂存，提交后才进入聊天记录，Agent 在提交后的下一步开始执行。补充需求、查询进度和修改作品均需再次主动唤醒。唤醒方式尚未接入真实硬件。

语音、AirPlay、Agent 执行及断线恢复均为预设剧情模拟。本版本没有调用麦克风、AirPlay 协议栈、Claude Code 或其他 Agent 服务，也不保存真实会话。刷新页面会回到第 1 步。

产品画面只有一个层级，不需要鼠标操作，也没有可点击的导航或链接入口。先展示共青森林公园、金山城市沙滩、上海博物馆东馆三个方案，每项只有一张资料照片、名称和两句简介；大家自由讨论，再由总发言人主动唤醒并确认开启投票，通过语音为金山城市沙滩投一票。

选定方案后，总发言人再次唤醒灵矽，说「就选金山城市沙滩，生成详细攻略」。提交并关闭麦克风之后，Agent 才开始新的攻略任务；检查时直接在同一项目预览区域展示金山攻略，完成后可继续语音改名为「金山城市沙滩 · 日落散步」。修改与断线重连均保留攻略和一票记录。长内容仅在预览区内部滚动，不撑高全页；不增加语音分页或真实语音查询功能。

主要步骤：第 12–17 步制作简洁方案，第 18 步讨论，第 19–21 步唤醒并开启投票，第 22–24 步语音投票，第 25–30 步再次唤醒、提交关闭麦克风、生成并检查金山攻略，第 31–35 步修改，第 36–39 步断线与重连。

金山攻略为半日建议，不含往返交通与排队时间；费用、开放和预约信息分开标注。产品画面显示简短来源名称及 2026-10-23 核验日期，原始研究来源和图片出处链接留在本说明中。

## 运行与发布

这是无需构建的静态站点。静态根目录为 `dist`。在仓库根目录运行：

```sh
python3 -m http.server 8080 --directory dist
```

浏览器打开 `http://localhost:8080`。部署时将 `dist` 作为静态目录，并为托管服务单独配置访问权限。

现有演示：https://lingxi-voice-prototype.livelydell4096.chatgpt.site（公开可访问；GitHub 源码仓库仍为私有，二者权限独立）。

方案背景：[灵矽产品方案分析](https://chatgpt.com/c/6adae580-8d14-83ec-865c-9eaa25300083)。

本仓库为私有仓库，用于内部方案展示和代码协作。

独立页面由 Visualize 的 `scripts/render.py` 从源片段导出，并将内外文档语言设为 `zh-CN`。外层固定为浏览器可用视口，源片段通过弹性布局适配高度；请保留包装页中禁用内容自动撑高的设置。图标使用导出包装中的固定版本 Lucide；本原型不发起业务 API 请求。
