# ADR 0001：本地 Web 工作台

日期：2026-10-23。状态：采用；后续取舍用新 ADR 更新。

## 背景

现有 HTML 原型演示了会议室语音创作。目标是在同一台 Mac 上运行工作台、Code Agent 执行端和灵矽客户端，浏览器分别显示电脑操作台和电视画面。团队已确认采用 React + TypeScript + Node.js。

## 决策

| 范围     | 选择                                                  | 原因                                       |
| -------- | ----------------------------------------------------- | ------------------------------------------ |
| 界面     | React + TypeScript + Vite                             | 两端共享组件、协议，便于嵌入预览和点选能力 |
| 本地服务 | Node.js 24 + Fastify                                  | 管理本机进程、项目、凭据与事件             |
| 工程组织 | npm workspaces                                        | 分清网页、服务和协议，暂不增加构建编排层   |
| 命令接口 | HTTP + Zod                                            | 三种输入共用运行时校验与请求语义           |
| 状态推送 | SSE                                                   | 当前输入少、单向更新多，浏览器自带重连     |
| 持久化   | SQLite + better-sqlite3                               | 无独立数据库进程，事务保证版本和请求去重   |
| 测试     | Biome、TypeScript、Vitest、Playwright、GitHub Actions | 静态、状态、接口、浏览器和跨平台验证       |

Codex 的 stdio 和灵矽的 WebSocket 各自封装在适配器中，不要求浏览器直接连接 Agent 进程或持有供应商密钥。

## 代价

- SQLite 同步访问面向单机规模；长时间构建、截图和模型调用不能阻塞 HTTP 处理。
- better-sqlite3 为原生依赖，安装可能需要预编译文件或本地编译，CI 因此覆盖 macOS。
- 当前单会话使用带 `schemaVersion` 的持久快照。真实任务与成果增多后再加专用表及迁移；不手改用户数据。
- SSE 连接总是发送完整快照。高频日志将来可单独增加增量流。
- Node 固定 24.x，npm 固定 11.x，依赖版本由锁文件固定。

## 延后选择

Electron/Tauri 留待系统级音频、托盘和投屏自动化需要明确后再评估。Python 暂无专属计算需求；如供应商 SDK 需要 Python/C++，可作为独立进程接入。单机版暂不部署云端业务数据库。

当前输入适合 HTTP + SSE；供应商音频仍可用 WebSocket。A2UI 留给动态决策卡，固定工作台先用 React。

## 本次范围

工程、会话保存、建议、同步、测试与文档。真实 Codex、灵矽、麦克风、项目预览和自动 AirPlay 未实现，状态显式标为待连接。
