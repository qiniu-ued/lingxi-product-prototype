# ADR 0006：每轮 token 消耗与缓存命中率

日期：2026-10-24。状态：本分支实施。沿用 CLI 0.163.0 的 `thread/tokenUsage/updated` 契约，不增加模型调用。

## 计算口径

一轮可能含多次模型请求。`last` 只表示最近一次请求，不能当成本轮全部消耗。取本轮最后报告的线程 `total` 减去本轮开始前的累计值，逐项计算总量、输入、输出、缓存读取/写入、推理；重复通知只是替换快照，不再相加。上下文占用仍沿用 ADR 0005 的 `last / window`，与本轮消耗独立。

缓存命中率 = 本轮 `cachedInputTokens / inputTokens`。缓存读取/写入是输入子项，推理是输出子项，不重复计入总量。不用总 token 作分母，也不把缓存写入当成命中。缺失缓存数据、缓存读取超过输入时不显示百分比；零输入显示不适用。

新建空线程基线是已知的零。已有线程只采用对应前驱轮次报告的累计值；没有可靠基线（包括新 fork 的继承上下文）则不可计算，不使用最近请求猜测。必要累计计数下降表示重置，整轮消耗不可计算；可选子项缺失/下降仅保留为未知。最近请求占用在压缩后下降不表示累计计数重置。

## 事件和历史

任务提交前保存基线记录；`turn/start` 返回真实 turn ID 后绑定，早到通知沿用有界缓冲。用量记录必须匹配本机 task/conversation 和提供方 thread/turn ID。未知、非法、跨项目报告丢弃。

已知历史轮次的迟到报告仍保存到其记录。下一轮引用前驱记录，动态修正差值，避免把迟到的上一轮消耗归给下一轮。历史报告不能替换较新轮次的上下文占用。没有报告时不把未知显示成零；失败/中断仅展示截至最后报告的已知消耗，不宣称已经结算。结束后的统计以最后收到的报告为准，可能继续更新。

## 存储和交互

新表 `workspace_turn_usage_v1` 按 task UUID 保存原始基线、前驱 task ID、最后累计报告、重置标志及上报时间。HTTP/SSE 增加默认空数组 `turnUsage`，只为当前历史派生统计，并校验 task 的 Codex thread/turn ID。写旧 `workspace_state_v2` 时剥离该字段；`workspace_turns_v2` Task 格式不变。旧版本忽略新表，升级无需重写旧记录，缺少历史报告的轮次不回填。表内没有提示词、凭据或录音。

每个已结束轮次回复下方展示消耗和命中率；电脑端可展开缓存/推理明细，大屏只显示摘要。运行中不提前显示完成统计。重启和切换对话恢复独立历史。

## 验证

协议替身测试多次请求、重复、排队、完成前后与下一轮启动后的迟到报告、重启、缺失基线和 fork 隔离；纯统计测试重置和缺失子项。真实 SQLite 检查旧快照不含新字段。浏览器验证两轮独立显示、SSE 更新、未知/零输入和中断提示；真实 Electron 验证任务报告进入回复下方。它们不证明真实账户的模型调用或最终计费用量已验收。
