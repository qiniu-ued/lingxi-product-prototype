# ADR 0008：历史选段、只读讨论与草稿隔离

- 日期：2026-10-24
- 状态：采用

## 问题

整轮「添加到对话」不能表达对某段回复的引用；整轮 Fork 后还需要手工复制原文。切换 Sidechat 时共享输入区会混用尚未提交的文字和附件。折叠菜单也使已有 Token 与上下文数据不易发现。

## 决定

操作台在单条 user/assistant 消息内选择文字后提供「引用到对话」与「选段 Sidechat」，每段最多 16,000 字符。引用写入现有 `kind: text` 附件，保留正在编辑的回复，展开并聚焦输入区，不启动模型。

选段 Sidechat 仍调用共享 workspace fork 命令。可选 `quote` 请求字段包含 taskId、role、messageId、text，严格验证后以持久历史原文核对；user 消息只接受 `prompt` 来源。来源必须属于当前项目/选中对话，线程连接等待前后检查目标。完成后沿用既有只读、禁用 MCP、串行讨论策略。模型上下文继承截至来源轮次的历史，选段只是草稿焦点；用户填写问题后另行提交。

输入草稿按项目/对话键分别保存文字、附件、预览标记和转写草稿。异步回调保留目标键；选段 Fork 成功后向返回的子对话写入引用，带回讨论结论时向父对话写入附件，不覆盖已有回复。草稿只存页面内存，刷新或退出不保留。

操作台与被动大屏常显每轮用量和当前上下文摘要；详细统计仍位于每轮「⋯」与「工作区」。继续使用既有真实报告与未知状态，计算方式不变。

## 兼容与边界

`quote` 仅存在于命令请求，不写入 Task、Conversation 或 v2 状态 JSON，无数据库迁移。实际提交使用已有 contextAttachment schema；用量独立表保持不变。

不提供自动文件回退，也未接入 `thread/revert`。仅回退模型历史不会还原文件；真正的撤销需要文件检查点、手动修改保护及明确范围。本次也不增加自动唤醒词检测；「开始收音」仍为显式手动操作。

测试覆盖选段引用、无自动任务、来源拒绝、主/子草稿与结论回传、两端摘要及真实 Electron 窗口。模型、音频与 AirPlay 真机证据另行记录。
