# ADR 0009：本地中文唤醒与双端上下文详情

- 日期：2026-10-24
- 状态：采用

## 本地唤醒

灵矽的 WebSocket 协议接收唤醒后的 listen/abort 消息，不替 Mac 检测本地唤醒词。使用 [sherpa-onnx Keyword Spotting](https://k2-fsa.github.io/sherpa/onnx/kws/index.html) 的 Node 原生扩展，在服务进程的独立 Worker 内运行 CPU 检测；不把云端持续转写冒充本地唤醒。

用户先显式下载固定的 [zh-en 3M 模型](https://github.com/k2-fsa/sherpa-onnx/releases/tag/kws-models)，约 33 MB。下载有超时和大小上限，校验固定 SHA-256 后仅解压指定的 encoder、decoder、joiner、tokens 四个文件；模型存入用户数据目录 `wake/`。不接受任意 URL、归档路径、可执行文件或参数，不修改模型、配置或音频到仓库。原生运行库按目标平台由 npm 安装，桌面包沿用已有打包流程；模型独立按需下载。

操作台连接灵矽后显式开启，默认“丽塔同学”，允许本次会话设置 2–12 个中文字符；pinyin-pro 生成声母/带调韵母，并按上游 ppinyin strict=False 处理 jqxy 的省略变音符号。检测到关键词仅标记唤醒，操作台取得当下项目、对话、标记、附件和文字草稿后才启动云端收音；提示音后说指令，不上传唤醒前的缓冲音频。单独唤醒不提交模型任务、不提升权限。

唤醒收音沿用已有 PCM16LE / 16kHz / mono / 20ms 私有 IPC。待唤醒帧只交给本地 Worker；任务收音才发给灵矽。唤醒后的语音停顿约 1.2 秒、且捕获至少 2 秒后结束；未检测到有效声音约 8 秒结束，仍保留总计 60 秒上限。普通 STT 形成草稿；设备 MCP 提交任务依然需要独立的语音控制授权。

检测开启期间如实显示麦克风已开启；播报期间暂停检测，操作台在本地播放积压和提示音期间传静音帧，阻止自身播报触发。音频帧有界，4 秒没有麦克风帧即停用。断开、关闭、刷新、退出及系统休眠会停止唤醒；不持久化启用状态，不自动恢复麦克风，不保存录音。检测失败保留手动收音入口。

## 上下文与回复操作

上下文默认为可点击的进度条，hover/focus 显示 `Context Window: xx/xx used.`；未知值只在提示与展开详情中说明，不伪造 0%。详情开关属于服务进程内存中的 UI 状态，操作台和被动大屏轮询同一状态，不写入严格的持久工作区/v2 Task。

鼠标通过固定 `context-details` 命令开关；语音通过 `workbench_context_details` 设备 MCP，同样受收音期限、项目/对话和已有语音控制授权限制。它不请求模型任务或改变权限。

每轮缺少 Token 报告时隐藏统计；已知值用一行灰色小字展示 total/input/output，只有可计算时追加缓存命中率。计算及独立用量表不变。引用与 Sidechat 仅从历史选段工具栏进入；从讨论带回原对话也选择需要的段落。Fork/复制为图标按钮，复制只写系统剪贴板；原生接口仅接受可信操作台的有界文本，不提供剪贴板读取。

## 验证边界

单元测试验证未唤醒不上传、唤醒不执行任务、端点结束、音频租约、失败回收、下载校验及语音 UI 指令。浏览器使用真实 AudioWorklet 与合成麦克风流验证唤醒后捕获当下草稿和关闭时释放轨道；Electron 验证图标、剪贴板和双端布局。

Linux 实际运行 sherpa-onnx 2.0.0 与固定模型，验证官方下载/校验/解压、上游中文音频关键词检测、“丽塔同学”初始化和静音不触发。它不证明用户真人说出默认词时的准确率，不替代 Mac 双架构加载、M1 远场噪声/回声、灵矽真实音频或 AirPlay 验收。
