# ADR 0010：启动配置检查与三步向导

- 日期：2026-10-24
- 状态：采用

桌面操作台首次挂载工作台前，通过 `/api/setup/check` 并行汇总 Codex、灵矽、唤醒模型与麦克风权限。配置缺失、诊断失败或权限被拒时进入 `/setup`，按首个缺项定位到 Codex、灵矽或唤醒模型步骤。被动大屏与独立浏览器基础模式不受此启动门控影响。

向导单独展示约 33 MB 的模型下载步骤。下载按钮复用既有固定 `install-wake` 动作，完成后重新检查；模型文件齐全且原生库可加载才报告唤醒配置就绪。原生库诊断在有界 Worker 中加载模块，不创建关键词文件、检测流、模型任务或语音连接。进程退出时回收检查 Worker。

麦克风状态经私有 `microphone-status` 读取 macOS 状态；检查不弹权限对话框、不申请媒体流。未请求过权限是提示，拒绝/限制/读取失败是问题；用户可主动授权，也可首次收音时授权。

诊断始终只读：不安装、下载、登录、注册设备、连接 WSS、开麦或开启唤醒，不把已保存配置当作真实云端连接。单项失败不抹掉其他结果，返回公共失败分类，不泄露凭据与原始错误。诊断不能覆盖远场识别、过期云令牌或所有运行期故障，实际连接与收音仍需用户显式验收。

启动跳转发生在草稿与工作任务挂载前，不在执行中定时跳转。用户可明确选择“暂时用文字进入工作台”，该选择只作用于当前页面；刷新或重启重新检查。向导内部继续操作不用重新加载页面，不产生跳转循环，也不会自动启用语音。

API 新增 wake/microphone 诊断字段，旧响应解析为待检查/未知，不修改持久 VoiceConfig、Task 或数据库。将来多引擎实现后按选中引擎检查；目前只有 Codex 适配器，其他引擎评估见 `docs/multi-engine-options.md`。
