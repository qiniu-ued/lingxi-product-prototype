# 音频来源与回声排查

审计范围是桌面父进程、可信操作台、私有 Node 服务、PCM Worklet、唤醒 Worker 及打包权限，不包含用户自行在终端运行的录音程序。2026-10-24 的代码结论：应用请求系统默认音频输入，没有直接请求系统输出音频、屏幕共享音轨或回环采集。

## 实际链路

`VoiceControls.tsx` 是产品唯一的 `getUserMedia` 调用点，参数为 `audio` 单声道与 `video: false`，请求 `echoCancellation`、`noiseSuppression`、`autoGainControl`。没有指定输入 `deviceId`，因此使用系统当前默认输入。绑定表单中的设备 MAC 是七牛设备标识，与音频输入设备 ID 无关。

没有额外的供应商录音 SDK：七牛连接由服务端自有 OTA/WSS 协议适配器处理；sherpa 仅做本地唤醒推理。

选中的输入流通过 `createMediaStreamSource` 进入 `pcm-worklet.js`，转为 PCM16LE/16kHz/单声道/20ms 帧；Worklet 没有将输入样本写入扬声器输出。可信 preload 只发送固定帧，Electron 校验操作者、类型及 640 字节后，通过私有 IPC 交给 Node。待唤醒帧只进入本地 sherpa KeywordSpotter；服务启动即连接已有绑定，使用 hello/ping 保持连接；这些消息不含待唤醒音频。识别到词且服务已就绪后，才为正确项目暂存上下文并进入本轮采集；只有有效收音状态发送 WSS 音频。

未发现 `getDisplayMedia`、`desktopCapturer`、display-media handler、loopback 音源、MediaRecorder、ScreenCaptureKit/AVAudio/PortAudio 等系统录音入口。`capturePage` 只获取作品 WebContents 图像，不获取系统屏幕或音频。作品的独立 session 拒绝媒体权限；只有可信操作台允许请求音频。sherpa 原生库在 Worker 内接收现有 PCM 数组，不自行打开录音设备；保存的 `active-keyword.txt` 是关键词文本，不是录音。

本地不保存录音文件。工作中有短暂内存帧/前缀缓冲，关闭后清理；提交给 Codex 的文字与任务会按历史持久化。云端收到唤醒后音频的保留策略取决于七牛服务与账号配置，不能由客户端代码证明云端不留存。

## 三种声音来源

| 情况                                          | 代码能说明什么                                                   | 如何核对                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 应用直接采集系统输出                          | 当前没有这条内置路径，也未申请对应屏幕/系统音频权限              | 检查系统授权项及是否运行其他录音工具                                             |
| 外放进入物理麦克风                            | 仍然属于麦克风采集；回声消除不能保证过滤其他播放器或所有远场声音 | 使用同一物理麦克风，对比耳机与外放                                               |
| 系统默认输入为 BlackHole、Loopback 等虚拟回环 | `getUserMedia` 会采集这个默认输入，耳机也可能仍收到电脑音频      | 在 macOS 声音设置核对输入，再看应用「语音唤醒 → 音频来源与回声」中的实际轨道名称 |

不能在没有设计师设备信息和对照试验的情况下，确认她遇到的是哪一种。

## 应用自己的播报

已排队的 TTS 播放期间抑制输入帧，最后一个播放源结束后保留 600ms 尾音缓冲，之后恢复正常输入。麦克风流仍存活，明确关闭按钮随时有效。已知播报期间暂停唤醒/上传，当前没有声学全双工打断能力；可点击停止播报。这个限制不应被描述为能过滤电脑里所有声音。

「音频来源与回声」显示当前输入轨道名称及 `getSettings()` 实际报告的回声消除、降噪和自动增益状态；不把请求的 `true` 当成浏览器已经生效。未报告时明确说明未知，设置与输入名称只留在当前操作台页面，不保存或上报设备清单。

## 最小 Mac 对照验收

先使用用户自己的测试项目、现有绑定和已授权的麦克风，不为测试新增系统音频录制权限。记录应用提交、实际 macOS 版本、输入名称、实际处理设置、是否外放和任务编号即可，不需要上传录音或令牌。
1. 物理麦克风 + 耳机：说唤醒词，确认能正常进入会话；应用播报含“丽塔同学”的文字，确认不会自己再次触发。
2. 同一物理麦克风 + 外放：重复应用播报并等待结束，核对尾音是否误触发；再播放其他播放器，观察是否发生声学串音。
3. 耳机 + 其他播放器：若仍能清晰识别播放器内容，检查默认输入是否为虚拟回环设备或存在额外采集工具，不能直接断言应用录制了系统音频。
4. 如本来就有虚拟输入，可与物理输入对照；不要求为了验收安装或授权虚拟驱动。
5. 每次点击「关闭语音」核对轨道释放与唤醒停止；重新打开应用后，显式关闭的选择应保留。

云端回归使用合成 MediaStream、真实 AudioWorklet、本机 WSS 与独立协议替身，验证帧来源、播报与尾音抑制和恢复。它们不等于 M1 麦克风、扬声器回声或七牛真人语音已经验收。
