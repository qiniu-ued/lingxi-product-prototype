# Mac 首次运行与连接准备

适用于只有 Codex 桌面应用、尚未创建丽塔同学账号的起点。启动会自动检查配置，缺项时进入向导，全部通过则直接进入工作台。日常从右上角常驻「设置」管理 Codex、丽塔同学与语音执行、语音唤醒与麦克风，也可从设置打开「连接向导」。明确打开的向导或设置不会因检查通过而自动退出。真实账户与音频仍需本机验收。

## 先打开应用

推荐下载对应架构桌面 ZIP，解压后把 `Lingxi.app` 放到「应用程序」并打开。M1 Pro 选择 `darwin-arm64`。桌面包内置 Node/npm，不需终端启动，退出用 Cmd+Q 或关闭操作台。未签名开发包的系统首次放行、下载步骤和回退见 [部署文档](deployment.md)。

源码开发使用默认分支、Node 24 / npm 11：`npm ci` 后 `npm run desktop:dev`。终端/浏览器备用模式见部署文档；打开向导已经说明应用在运行，向导内不重复指导安装工作台本身。

向导显示的是服务所在电脑的系统、架构与 Node 版本；桌面版额外显示具体系统版本。云端测试不能当作 Mac 配置成功。

## 先检查配置，再按缺项操作

桌面启动和向导使用同一个只读检查，返回本地服务、Codex、丽塔同学、唤醒模型与麦克风权限，再展示三步配置建议：配置 Codex、配置丽塔同学、配置唤醒模型。自动定位首个缺项；缺少 CLI 才显示安装按钮，未登录才显示授权按钮。丽塔同学检查仅判断本机是否保存连接配置；没有配置则提示绑定设备。检查不发起设备注册或收音，也不把“已保存配置”当作云端连接成功。模型检查确认文件齐全和原生库可加载，不能代替真人唤醒验收；麦克风状态查询不会弹授权框。尚未请求权限不阻止进入工作台，拒绝/限制或状态读取失败会提示处理。

缺项时可以先「暂时用文字进入工作台」，该选择仅作用于当前页面；刷新/重启后重新检查。没有循环跳转，也不会在编辑或执行中定时强制跳转。向导可点击「重新检查全部配置」；第三步下载完成后会自动复查。

工作台内打开「设置」或「连接向导」会保留当前页各对话的未发送文字、附件及运行中的任务，但停止本页录音、唤醒检测和播放；返回可按自动唤醒偏好与既有授权恢复本地监听，不恢复云端收音。手动刷新、退出或直接加载另一页面仍会丢失内存草稿。可直接访问 `/settings#codex`、`/settings#lingxi` 或 `/settings#wake`；桌面录音与任务能力仍要求应用内的可信页面。

只读检查调用 `codex --version`，短暂启动 `codex app-server`，完成 `initialize` / `initialized`，再调用 `account/read`（`refreshToken: false`）。读取登录类型后关闭进程。检查不会安装、登录、创建线程或执行任务，不直接读取凭据文件；邮箱、密钥和原始提供方错误不会返回页面。同一时刻的检查共享运行，超时或异常后回收子进程。

### 通过页面安装与登录

- 缺少 CLI：点击「一键安装最新版 Codex」。本地 Node 服务调用固定的 `npm install --prefix <工具目录> --save-exact --no-audit --no-fund @openai/codex@latest`，需要 npm 和网络。使用稳定通道最新版，安装完成后报告实际版本，并检查 App Server 协议是否可用。
- 安装位置：数据库所在目录的 `tools/codex-<UUID>/`，运行包默认在 `~/Library/Application Support/Lingxi/tools/`。每份安装保留 npm 的 package.json 与锁文件；验证通过才原子切换 `codex-current.json` 指针。失败不替换原来使用的安装。已有全局 CLI 不自动升级，也不需要 sudo。
- 尚未登录：点击「在浏览器登录 Codex」。本地服务通过 App Server 的 `account/login/start` 发起 ChatGPT 登录，在官方网页完成授权。如果浏览器拦截新窗口，点击「打开官方授权页」。服务等待与该次 loginId 对应的完成通知，再复查账号配置；不让网页收集密码或 token。
- 页面刷新后会继续读取当前操作。可停止安装或停止等待登录；关闭工作台服务会回收它启动的进程。停止不撤销已经完成的安装或授权。操作状态保存在服务内存，服务重启后会重新检查实际环境；重启不会自动重试安装或登录。请求 ID 在当前服务内去重，最多保留最近 20 次记录。

浏览器本身不能执行 shell。按钮只请求本地服务的固定安装、登录、取消操作，接口不接受命令文本、程序路径或参数。操作串行执行，安装和登录 POST 必须具有允许的本地 Origin；服务仍只监听回环地址。丽塔同学设备绑定见下一节；官方账号登录与设备授权仍在七牛页面完成。

### 终端备用方式

也可以保留工作台运行，在另一个终端标签页自行配置。只有桌面应用时需安装 CLI；已有 CLI 先检查即可：

```sh
npm install -g @openai/codex@latest
codex --version
codex login status
# 未登录时再执行
codex login
```

页面安装由工作台单独管理，终端里的 `codex` 可能指向另一份安装。服务选择顺序为 `LINGXI_CODEX_BIN` → 工作台管理的 CLI → PATH 中的 CLI。设置了自定义路径时，页面不另行安装一个不会被选用的版本；请在终端维护该安装。首次使用 PATH 安装若找不到程序，执行 `command -v codex`，从相同终端重新启动工作台；也可指定可执行文件的绝对路径：

```sh
LINGXI_CODEX_BIN="/absolute/path/to/codex" npm start
```

路径不能包含命令参数。诊断通过仅表示版本命令、App Server 握手和认证配置可读取，不代表模型调用、额度或项目权限已验证。向导不会接管 Codex 桌面应用已有会话；桌面版的真实任务入口已经接入，仍需本机模型调用验收。测试使用固定的协议替身验证契约，用户安装入口使用 latest；任务适配器参照 CLI 0.163.0 生成的 v2 类型，通过子进程协议替身测试；latest 发生协议变化时需更新适配。

## 在向导内绑定丽塔同学

1. 打开「配置丽塔同学」，从官方链接登录七牛控制台并创建智能体。不要把账号密码或令牌发给开发者。
2. 点击「获取本机绑定码」。应用为这台安装生成稳定的设备标识和 UUID，经官方 OTA 网关申请六位激活码；在官方控制台的设备绑定入口输入该码，并选择智能体。
3. 回到向导，点击「我已绑定，检查连接配置」。向导检查激活状态，再自动获取官方 WebSocket URL 与令牌，由 macOS 加密保存。不会下载安装 OTA 响应中的固件，也不需要复制令牌。
4. 点击「连接丽塔同学」，确认真实握手成功，再点「开始收音」。首次需在 macOS 允许 Lingxi 使用麦克风；日后在「系统设置 → 隐私与安全性 → 麦克风」修改。主动开启后保持语音会话，停顿只结束本句话并等待回复，播报后可继续说；点击「关闭语音」才结束会话。无需编译 C++ 客户端或安装 Homebrew。
5. 点击「测试播报」，确认听到声音。「停止播报」只停止 TTS；「停止任务」才中断 Codex；停止或失败会暂停尚未发送的排队输入。任务结束/失败/等待回答的状态也会请求语音通知，需真机核对声音。核对 macOS 输入和输出设备，AirPlay 后也要重新检查声音路由。
6. 工作台里的转写先作为草稿；可将转写放入指令或问题答案，补上鼠标标记和键盘内容，再提交。若希望直接用语音发任务，在「设置 → 丽塔同学与语音执行」（或向导第二步）开启「允许主动收音后用语音提交/停止任务」，然后重新连接。七牛智能体的「技能与扩展」选择「统一意图识别」，聊天模型须支持工具调用，保存后重新连接。「无意图识别」只聊天，不会调用工作台。可展开「配置语音工作台角色」复制说明到云端角色介绍。丽塔同学通过端侧 MCP 使用同一个任务入口，一次收音最多一个任务，结束后 30 秒不再接受指令；切换项目或对话后旧收音无效。不能用语音批准额外系统权限。

绑定码失效时重新获取；检查异常时核对网络和官方控制台，不以文字“已绑定”替代握手结果。高级设置可手动填入已绑定设备的 MAC/令牌，但通常无需使用。

### 能聊天，却说不能修改页面

先看右侧是否新增 Codex 任务及「语音交接状态」。没有任务时，语音回复来自云端语音智能体，还不能判断 Codex 的能力。按顺序核对：
1. 「设置 → 丽塔同学与语音执行」显示已开启语音执行；修改后重新连接。默认仅转写，开启唤醒也不会授权执行。
2. 云端使用支持工具调用的模型与「统一意图识别」。官方[智能体配置](https://linx.qiniu.com/docs/xrobot/guide/agent-config)明确区分工具意图与普通聊天；工作台通过 WSS 内的[设备 MCP](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)提供工具，无需把回环服务注册成公网 MCP。
3. 工作台已有项目，主动收音后说“把这个页面变成粉色”。交接区会显示工具列表是否被读取，以及未授权、项目缺失、窗口过期或上下文变化等具体原因。工具列表已读取仍不保证云端一定调用。
4. 只有「已交给 Codex」和实际任务编号出现，才进入了开发流程；任务完成以右侧真实进度为准。未交接可使用转写草稿手动提交，不会自动重放或将普通转写自动执行。

角色说明与 MCP `instructions` 是给云端的提示，不能代替实际工具调用，也不自动修改控制台设置。若仍无调用，需要在本机账号核对智能体配置与云端记录；不要提交令牌或录音。

当前音频协商为 PCM16LE / 16kHz / 单声道，20ms 定长帧。若服务返回 Opus 或其他格式，会明确提示不兼容；本版不会把错误格式播放成噪声。需要与真实账号一起确认 PCM 支持。新安装与旧配置缺字段时默认自动连接已有绑定并在模型、现有麦克风授权满足时监听“丽塔同学”；已保存 false 保留，待唤醒只在本机检测，不上传或保存录音。

设备标识在用户数据目录的 `voice-device.json`，凭证在 `voice-config.enc`，不进入 Git 或 HTTP 状态响应。换 Mac/系统账号后若无法解密，应重新绑定。删除应用安装目录不会删除用户数据，常规升级不应清空这些文件。

## Codex、作品与大屏验收

回到桌面操作台，新建/打开允许修改的项目，要求“在 preview/index.html 做一个周末出游投票页”。核对真实文件和预览后，再要求“给金山城市沙滩投一票”。Codex 的 MCP 指向大屏窗口的同一个页面，操作台显示它的截图；纯页面操作不应导致重载。点击预览旁「批注修改」再点目标，在「给选中元素的批注」中填写要求，可直接提交，也可把标记加入上下文；作品版本变化后重新选取。

检查一次批准/拒绝和停止任务。应用重启后核对已修改文件，未完成任务标为中断，不能自动重放。对话历史可以切换，执行中可排队/补充，结束轮次可以创建 Sidechat 或 Fork；Fork 共享项目文件，未提供代码回退或独立 worktree。

在 macOS 控制中心手动连接 AirPlay，应用启动就会打开大屏窗口，即使尚无项目也有空状态；支持扩展显示时优先使用已有外接屏，必要时自行移动窗口并全屏。电视 PIN 由系统处理，当前不支持语音自动连接。核对远距离阅读、画面重连、声音路由。

记录 M1 Pro 的实际 macOS 版本、CLI 版本和应用提交。丽塔同学登录、官方页面授权及音频真机验证在用户本机进行；向导负责申请激活码、检查绑定并保存配置。自定义“丽塔同学”、自动摘要播报与系统自动化的后续步骤见 [设计对齐计划](desktop-voice-plan.md)。

已有框架项目：在工作台「终端」运行项目开发命令（例如 `npm run dev -- --port 5174`），再在预览中填写真实显示的 loopback URL。该地址不能是工作台自己的服务端口；作品页面只能访问选定项目服务及其 HMR WebSocket。

## 模型与上下文

项目打开后，展开底栏「文字输入」，在输入框上方选择模型和 Reasoning Effort；模型列表自动读取。切换模型会采用其兼容默认强度。读取失败可刷新，原选择保留。执行中改选用于后续新提交，排队轮次保持提交时设置。

对话区底部默认只显示上下文进度条，hover 显示 `Context Window: xx/xx used.`；点击展开输入、缓存、输出、推理和累计明细，再点击收起。电脑与大屏共享开关；开启语音控制后也可说“打开上下文详情”。每轮有报告时显示一行灰色 Token/Input/Output/Cache hit，没有报告则隐藏，未知缓存比例省略。当前占用取最近一次模型请求，不把累计消耗或草稿当作当前占用。

每轮结束后，点击对应回复后的「⋯」（本轮详情），查看本轮 token 消耗和缓存命中率，展开“本轮用量明细”查看缓存读写及推理。该消耗包含本轮多次模型请求；缓存命中率按缓存读取/输入计算。连续完成两轮并退出重开，可核对两轮统计各自保留。尚未报告、缺少起始累计值或计数重置时不估算；无输入时命中率不适用，中断/失败只表示最后已报告的消耗。

## 工作模式、权限与工具

展开「文字输入」，选择「执行模式」或「计划模式」。计划模式使用 Codex 内置的官方计划指令；讨论完切回执行模式，再提交实施要求。可在其中的「模式说明与兼容验证」点击「验证执行设置」，检查本机 CLI 是否接受计划/执行模式及权限设置：这会创建独立临时会话，检查后关闭，不请求模型执行，不改变当前对话或项目。界面只列出实际确认的项目。验证失败可先在向导检查 CLI 和登录、更新 latest，并确认 Codex 配置目录可写。

权限默认 Manual，额外权限由你审批；Approve for me 保留工作区沙箱，由 Codex 自动审查越界请求，可能拒绝；Full Access 允许沙箱外文件与网络，通常不逐次询问。只选择你打算授予的访问范围。组织策略不允许的选项不可选，服务会再次检查；Sidechat 不继承完整访问，始终只读。选择在提交/入队时捕获，修改只影响新任务。

丽塔同学连接后开启允许语音控制，再主动收音说“切换到计划模式”或“切换到执行模式”。设备工具调用成功后播报切换结果；普通转写仍保留为草稿。每次收音最多切换到一种模式，权限级别在操作台选择。

通过「工作区 → 工具与额度」查看技能说明和启用状态、MCP 连接/登录状态与工具说明，以及额度进度和重置时间；点击读取或刷新。未知额度不代表充足，提供方暂停普通额度时会明确提示。这里仍是只读目录，未提供插件安装、MCP OAuth 或配置编辑。

底栏集中显示真实麦克风状态；「开始收音」提供手动入口；默认本地唤醒会在条件满足时自动开启，底栏可关闭并记住选择。连接后可在「更多语音操作」（⋯）断开，会话中随时可关闭语音，播报中可停止播报。提交成功后文字输入面板收起，输入失败仍保留草稿；点选元素、添加上下文或使用转写草稿时会自动展开。

选中单条历史消息中的文字，可在浮动工具栏「引用到对话」，保留已写回复；也可对已结束轮次「选段 Sidechat」，继承截至该轮的上下文，并把选段加入新讨论的草稿。填写问题后再提交，Sidechat 与主任务串行。每次选段最多 16,000 字符，不跨消息。切换对话保留各自文字和附件草稿，刷新/退出后不保留；讨论结果可带回主对话的草稿。

当前没有撤销上一轮或自动文件回退。停止任务后请核对已有修改；Fork 也不恢复代码。对话历史回退与文件回退是不同能力，不能用清除聊天记录代替撤销修改。

## 开启“丽塔同学”本地唤醒

1. 在「设置 → 语音唤醒与麦克风」（或向导第三步）点击下载模型，约 33 MB，仅从固定 GitHub release 下载并校验；无需额外唤醒服务账号。下载失败时核对 GitHub 网络可达性后重试。
2. 同页可将默认“丽塔同学”改成 2–12 个中文字符，点击「保存本次唤醒词」；仅本次服务运行生效，检测开启时先关闭。连接丽塔同学，回工作台展开底栏「语音唤醒」，有既有授权时自动监听；首次在设置明确点击允许麦克风，自动路径不弹授权。状态应显示“本地待唤醒 · 麦克风已开启”。设置页本身不启用检测。
3. 说出唤醒词，听到短提示音后再说要求；不要将唤醒词与指令连续快速说完。唤醒前的音频不上传，也没有前置录音缓冲。停顿约 1.2 秒会结束收音（最少捕获约 2 秒）；无声不会关闭会话；单句话按静音或 60 秒边界分段，播报结束后保持本机等待，后续讲话无需重复唤醒。
4. 普通转写仍进入草稿。如需直接提交任务、切换模式或打开上下文详情，先在「设置 → 丽塔同学与语音执行」明确允许语音控制并重新连接，确认丽塔同学调用对应设备 MCP。唤醒本身不等于授权模型执行，不允许语音提升权限。
5. 播报时暂停上传，播放结束后继续等待讲话；点击「关闭语音」或说“关闭语音”关闭整个会话及唤醒。明确关闭后会保存 off；应用重启按偏好恢复本地唤醒，网络/音频故障及休眠在本次运行中暂停。音频中断会停用检测并提示重试。

模型在用户数据目录 `wake/`，应用升级保留模型；启用状态与本次自定义词不跨重启恢复。首次 Mac 安装还需确认 sherpa 原生库可以加载；当前已验证 Linux 下载/校验/初始化与上游中文测试音频，M1 真实人声、多人讨论、距离和回声仍待验收。建议分别在近讲、沙发和会议室记录漏检/误唤醒，勿将原始录音、令牌提交仓库。

“关闭语音”使用设备工具 `workbench_voice_close`，即使未授权语音提交也可关闭，不中断 Codex 任务。主动会话的待说话检测留在本机；进入本次会话后保存有限的内存语音前缀，检测到讲话后为新轮次暂存上下文再上传，不保存录音文件。进入设置会暂停采集，返回按偏好检查；音频流丢失和网络断开暂停当前运行，不能自动重放旧指令。可恢复的服务断连按偏好有界重连，不恢复旧收音，不以本地开麦假装服务可用。

默认唤醒词为“丽塔同学”。新安装的自动本地唤醒偏好为开；升级时已有数据库却没有长期偏好记录，无法恢复用户过去是否主动关闭，因此显示一次确认。勾选后保存，后续启动无需手动切换。关闭、撤销授权或模型不可用不会被默认值覆盖；偏好文件损坏时先关闭并提示修复。未绑定语音设备也可本地等待，识别唤醒后会给出绑定指引，不自动创建设备。来源、回声和耳机/外放对照见 [音频说明](audio-input-and-echo.md)。

自动连接与本地唤醒是独立设置。底栏显示真实服务连接与退避状态；「更多语音操作 → 断开语音服务」只关闭连接，不能被唤醒或网络恢复覆盖。「关闭语音」同时停麦、关闭唤醒和服务，记住选择。正常静音不关闭会话；断网恢复不重放已说过的命令。

「批注修改」现在会在鼠标悬浮时实时框选元素，并显示标签和尺寸。点击后锁定目标、打开批注输入；Esc 或「取消批注点选」取消。模式内滚轮滚动唯一作品页面，批注高亮不触发其中按钮、导航或表单。电脑仍显示同一页面的截图，不创建第二个浏览器状态。支持嵌套元素和同源 iframe；跨源/不透明 iframe、旋转或透视变换的 iframe 按容器整体选择。高亮只在电脑侧显示，已选元素引用仍进入原 Codex 任务。

项目操作采用右上角「新建项目」分体按钮，下拉可打开已有项目或刷新作品；「设置」和「工作区」保持可见。绿色连接徽标只表示语音服务在线，麦克风图标分别表示本地监听/收音；服务断线时，本地唤醒仍可能开启。已有项目的执行、等待确认和预览未就绪提示继续保留。

故障后先保持应用开启，在「语音诊断 → 复制诊断日志」复制脱敏阶段；失败时使用面板中的手动复制文本。不要发送整个用户数据目录。语音正文仅留本次应用运行的内存，与阶段日志分开；没有项目也能聊天，任务提交仍需项目。详细步骤和保留边界见 [语音诊断](voice-diagnostics.md)。

摘要不能还原正文。详细调试现在随服务启动持续记录，不需要勾选，也没有启停选项；复现后在同面板预览，再用「复制详细日志（含对话内容）」单独复制。它包含对话和项目内容，仍经过凭据脱敏，可能截断，非原始抓包；只保留本次运行的 64 条/10 分钟、每条最多 8192 字符，不录音、不写磁盘、不自动上传，退出清空，清空后继续记录。不会因此申请麦克风权限或开始收音。

自动连接、语音执行和本地唤醒在新安装与旧配置缺字段时默认开启；可识别的 legacy-review 旧默认会迁移，已保存 false 保留。已有加密配置中的 false 无法区分旧默认和主动关闭，因此保留；可在设置手动调整并重新连接。缺模型、未绑定或系统未授权仍需正常配置。见 [ADR 0014](adr/0014-default-voice-and-always-on-diagnostics.md)。
