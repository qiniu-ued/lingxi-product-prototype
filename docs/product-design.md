# 产品设计：共同看着产品做出来

首版设计基线，2026-10-23。团队已确认使用 React + TypeScript + Node.js。

## 场景与目标

- 沙发：一位用户、一台 Mac 和电视，用语音提出任务，偶尔回电脑做精细操作。
- 会议室：大家讨论，一位操作者汇总并提交修改，共同观看成果与执行进展。

首版聚焦本地前端项目。执行和文件位于 Mac，模型与语音能力联网调用。后续再考虑多电脑加入和同时编辑代码。

## 混合输入

语音说明意图，鼠标指定对象，键盘提供准确文本。三种输入进入同一会话。例如选中首页标题，说“标题大一点”，再键入“周末，一起去哪里？”。提交应包含文字、目标、成果版本和必要截图。

区分画面操作（滚动、放大、指向、切换成果）和项目修改（文字、样式、交互、代码）。预览提供“体验”和“选择修改”模式，点选目标时不触发页面原有按钮或表单。

操作台作品画面支持鼠标滚轮和触控板滚动，传递到大屏中的同一个页面，包括页面内部滚动区。批注时也可先滚动再选择元素；滚动不提交模型任务或刷新作品。见 [ADR 0014](adr/0014-operator-preview-scrolling.md)。

普通预览可直接点击体验作品按钮，例如选择投票目的地并提交；开启“批注修改”后，点击只选择元素，不操作作品。体验操作不启动模型任务，作品自身负责计票和保存。见 [ADR 0015](adr/0015-operator-preview-clicks.md)。

目标携带 `artifactId / artifactRevision / elementId`，大屏同步高亮。版本变化后重新核对目标，不凭旧坐标猜测。DOM 到源码的映射需要预览工具支持，首版不承诺任意网站、canvas 或桌面程序的自动源码定位。

## 讨论与执行

首版由一位操作者提交集体意见。讨论中的“要不要换个布局”先进入建议列表，达成一致后再发起执行。
- 输入草稿、保存建议和开始任务是不同状态。
- 执行沿用 Codex 权限、询问和审批设置。
- 执行中可补充要求或中断；停止播报和停止任务分别处理。
- 记录建议来源与顺序，保留本轮变化和验证结果。

## 两种视图

大屏以成果为主体，显示目标、实际阶段、待决定事项和本轮变化。使用远距离可读的字号，完整日志放电脑端；长内容需支持画面滚动。

电脑端提供输入、元素选择、建议列表、任务历史和项目配置。选择、高亮、提交和成果切换同步到大屏。

修改期间保留当前可用成果，新版本准备好后切换。成果版本切换与撤回代码修改分别设计。

成果自动更新时保留操作台焦点与大屏窗口的现有可见状态；首次自动发布创建大屏时在后台显示，主动点击“打开大屏”才切到大屏。用户提供设计原型时，生成作品应沿用其字形、间距、颜色和图片表现，不自行增加渐变、图片阴影、说明或页面层级。

## 状态与恢复

- 语音：待激活 → 收音 → 转写草稿 → 提交 → 结束收音。
- 任务：建议 → 待执行 → 执行中 → 完成 / 失败 / 已中断；另有待用户输入状态。
- 连接：连接中 / 已连接 / 已断开。屏幕断开不取消任务。

待激活时不上传普通讨论。默认在现有授权和模型可用时本地监听“丽塔同学”，也保留按键主动激活；不把“麦克风完全关闭”和持续监听唤醒词混为一谈。部分转写不得自动执行。

会话、建议、任务标识和成果索引持久保存。重连恢复最新画面；服务重启后，未终结任务向真实 Agent 查询或标为待核对，不自动认定成功。

## 首个可用版本验收

1. Mac 连接麦克风和大屏，打开操作台与大屏视图。
2. 提出页面需求，Codex 真正修改指定项目并启动预览。
3. 鼠标选元素、语音说明意图、键盘补文案，再改一轮。
4. 大屏展示成果与实际验证信息，可继续体验。
5. 断开并恢复大屏，任务和成果保留。

当前桌面版本实现常驻多轮对话、终端、Diff、提问/审批/停止、Sidechat/Fork、附件、排队/补充，以及静态或本机框架服务的唯一页面。丽塔同学提供向导内绑定和手动 PCM 音频适配，尚待真实账号/硬件验收。浏览器基础模式仍只保存建议。本地中文唤醒已实现协议和原生推理链路，远场与 Mac 仍待验收；子 Agent 树、独立 worktree和 AirPlay 自动化待实现。

桌面视觉对齐设计师的浅暖色两栏布局，左侧作品、右侧对话与紧凑的实际 Codex 进度，底栏集中麦克风状态和语音操作。项目、对话、终端、Diff、工具与上下文明细集中到「工作区」；文字、模型、模式和权限位于默认折叠的「文字输入」。每轮有用量则在回复下方显示一行灰色小字；上下文默认只展示进度条，hover 提示，点击或语音可在操作台与大屏同步展开。引用/Sidechat 只保留选段入口，Fork/复制为图标按钮。选中单条历史消息的文字可引用到草稿，或从已结束轮次创建只读 Sidechat；选段不自动提交，Sidechat 继承截至来源轮次的历史。各对话草稿在当前页面内分别保留。辅助内容在面板内滚动，操作台与大屏均保持单屏布局。不展示模拟 AirPlay 连接或假 PIN，不把截图镜像当成第二个互动页面。纯作品操作也交给 Codex，根据 MCP 当前绑定执行；代码未变时不刷新预览。当前 UI 保留并可切换多轮历史，持久回执用于重试去重；完整能力与限制见 [能力表](workspace-capabilities.md)。

启动先汇总 Codex、丽塔同学、唤醒模型与麦克风配置，有缺项或失败则进入三步向导；默认不自动下载、登录或开启语音。用户可选择当前页面先用文字，刷新/重启重新检查；大屏不跳入配置页。多引擎工作台为后续提案，见[评估](multi-engine-options.md)。

右上角常驻「设置」集中配置 Codex、丽塔同学绑定/语音执行、唤醒模型/关键词/麦克风；所有检查通过也保留页面，连接向导仍用于首次配置和故障处理。内页切换保留未发送草稿及任务，停止当前收音/唤醒，返回后由用户重新开启。双端语音交接状态区分仅转写、未交接/具体原因和真实任务编号；能聊天、能唤醒不等于 Codex 已接收任务。云端须启用意图识别及工具调用，不能仅靠角色文案承诺执行。

主动语音会话跨静音/播报保持，逐句重新暂存当前上下文，手动或设备工具可关闭；故障断连仅重连服务，不恢复旧收音。预览旁「批注修改」提供元素批注并进入真实任务，大屏启动默认打开，即使无项目也有空状态；AirPlay 仍由系统管理。可见品牌统一「丽塔同学」，技术标识与数据目录不变。详见 [ADR 0012](adr/0012-continuous-voice-and-preview-annotations.md)。

新安装启动即自动连接已有绑定的语音服务，并在模型与现有麦克风授权满足时本地监听“丽塔同学”；待唤醒音频不上传。连接通过保活与最多六次退避重试维护，失败状态如实显示。连接与唤醒选择分别保存在 voice-connection-preferences.v1.json、wake-preferences.v1.json；既有安装无记录时分别确认一次，损坏/无法保存时关闭。关闭语音会保存两项关闭；仅关闭唤醒或断开服务可分别操作。设置返回可按偏好恢复本地唤醒，重连不能恢复旧收音或重放任务。行为与兼容见 [ADR 0013](adr/0013-default-local-wake.md)，输入来源和物理回声验收见 [音频审计](audio-input-and-echo.md)。
