# 灵矽产品需求说明

## 产品定位

灵矽是一款面向多人共同讨论场景的语音应用。用户主动唤醒灵矽，通过语音调用 Claude Code 或其他 Code Agent 完成编程开发，并在公共屏幕上直接查看、体验和修改结果。

屏幕连接可以采用 AirPlay 或其他兼容协议，具体方案根据控制端与电视设备能力确定。

## 典型使用场景

一个社团在会议室讨论集体出游，成员想去的地方各不相同。大家先自由交流，由一位总发言人整理意见，主动唤醒灵矽制作出游方案和投票功能。开发期间，大家可以继续讨论；投票选定目的地后，再让灵矽生成该目的地的详细攻略。

这是介于正式工作与完全放松之间的集体活动。灵矽帮助大家把讨论转成可见结果，减少指定专人操作电脑的负担。

## 核心流程

1. 总发言人主动唤醒灵矽，语音连接会议室屏幕；需要配对时，通过语音完成设备选择与验证码提交。
2. 大家讨论后，总发言人提交需求。灵矽先制作几个真实景点的简洁方案，每个方案只展示一张实景图、名称和两句话介绍。
3. 方案展示后，大家继续讨论。总发言人再次唤醒灵矽，开启投票并通过语音提交投票信息，屏幕反馈票数与选择结果。
4. 选定目的地后，总发言人再次唤醒灵矽，要求生成详细攻略。Agent 完成后，攻略直接呈现在同一项目预览区域。
5. 用户可继续通过语音修改内容。修改及屏幕断线重连后，应保留已选方案、投票与当前项目状态。

## 语音交互原则

- 默认处于待唤醒状态，麦克风关闭，不采集大家的普通讨论。
- 每次指令都经过「主动唤醒 → 收音中 → 提交并关闭麦克风 → 开始处理」；提交前不启动本次 Agent 任务。
- Agent 执行期间保持麦克风关闭，大家可以继续讨论。补充需求、查询进度或修改内容时，需要再次主动唤醒。
- 由总发言人整理并提交集体意见，避免把成员间的日常交流误当作指令。
- 产品操作通过语音完成，无需鼠标点击。内容只在一个层级呈现，不设置“查看更多”、返回或多级页面。

## 屏幕呈现要求

- 项目预览与对话面板清楚分区；对话面板使用白色底色，并通过头像、气泡和左右布局体现对话关系。
- 对话记录持续保留，新消息追加在下方，不随步骤切换替换历史。
- Agent 以图标、名称和进度共同呈现，放在对话面板内。
- 普通状态使用灰色；完成、失败等状态使用有明确含义的提示色，并配合文字说明。
- 采用温暖、轻松的视觉风格。景点图片应真实、清晰、构图干净；投屏等待图标中的无线符号位于屏幕轮廓内部。
- 画面根据电脑窗口高度适配，连接前后屏幕区域保持一致，不因内容增加而撑高整个页面。

## 攻略内容要求

选定方案前只提供简短介绍；选定后才生成详细攻略，包括建议行程、交通、开放时间、费用和预约事项。景点及资料必须真实，官方信息与建议安排需要区分，无法核实的内容明确标注待确认，不编造票价、开放规则或活动。

实际语音、屏幕协议和 Code Agent 的接入能力需在真实设备上验证。
