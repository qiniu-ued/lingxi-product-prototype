# 语音对话与诊断

语音回复不等于 Codex 已执行。服务连接、读取工具列表、调用工具、获得 task ID 和执行结果是不同阶段。

## 给设计师的报障步骤

1. 复现后先不要退出或重启应用。打开右侧「语音交接状态 → 语音诊断」；也可从「设置 → 丽塔同学与语音执行 → 语音诊断」进入。
2. 点击「复制诊断日志」，看到“已复制”再粘贴发送。自动复制失败时，在出现的「诊断日志文本」框全选复制。
3. 同时说明发生时间和时区、当时说了什么类型的要求以及看到/听到了什么。日志自动带应用版本、构建提交、导出时间/时区；无需发送账号、令牌、录音、完整聊天、数据库或配置目录。
4. 问题发生后尽快复制，避免旧记录轮转。摘要和详细调试从服务启动持续记录，不需要启用，也没有停用选项；无法恢复旧版本省略或已轮转的内容。
5. 摘要不足时，在同一面板展开「预览详细日志（含对话内容）」检查后，使用独立的「复制详细日志（含对话内容）」；复制失败会出现详细日志的手动文本框。分享详细日志会包含你的对话和项目内容，不要把它当成无正文的摘要发送。可清空缓存，但后续会继续记录。

日志目前没有磁盘文件路径。摘要阶段信息只留在本机 Node 服务的内存环形缓冲，最多 128 条、最长 30 分钟，无计时器或后台上传。超限删除最旧记录；导出注明已丢弃数量。清空立即删除缓存但继续记录；退出应用清空，重启重新开始记录。刷新网页、正常语音重连不清空缓存，重启服务会清空。摘要不会保存原始音频、转写正文、提示词、工具参数、绑定 MAC/身份、密码或令牌；摘要复制按钮始终不包含详细调试正文。

事件含接收时间、应用生成的连接会话 ID、收音 ID、项目/对话 ID、真实 task ID（如有）、工具名、阶段和错误分类。连接 ID 不是云端设备身份。时间是客户端观察时刻，不是云端执行时间。复制的是脱敏文本，界面显示可读阶段，不展示供应商原始 JSON。

连接诊断还包含触发来源、枚举原因、WebSocket close code（如有）、是否收到明确关闭操作、重连次数和退避时间。`transport_close` 只说明收到关闭事件，1006 等不能证明是远端主动正常关闭；`keepalive_timeout` 是本地等待 pong 超时。`explicitClose` 说明工作台收到关闭操作，来源区分界面、语音工具、系统和配置，不证明说话人身份。服务状态、持续语音会话和本地唤醒分别显示；麦克风帧连续 4 秒中断会停止采集，不等于服务断连。重连不恢复旧收音，新的服务会话不再沿用旧 capture ID；已接受任务及结果仍关联原始会话。

## 持续详细调试

从服务启动持续收集，不提供启停选项；旧的停用 API 请求也不会关闭记录。无法恢复旧摘要中省略的原文。记录收到/发出的文本协议、STT 原文、助手文字、工具参数及返回结构、服务额外响应字段，以及连接关闭原因和必要错误字段。关联应用生成的 session/capture/task ID。它是**经过凭据脱敏、格式化且可能截断的详细 payload**，不是未经修改的原始网络包，不记录二进制音频、任意环境变量或整个本地配置。

已知绑定凭据与身份、嵌套密码/token/cookie/Authorization/密钥字段，以及字符串内的常见凭据格式，在长度截断之前遮盖。JSON 编码在字符串中的响应也先解析再脱敏。正文仍可能包含私人讨论、源码、项目名和路径，分享前必须预览；脱敏不等于正文可公开。

最多 64 条、10 分钟，每条 payload 最多 8192 字符，另有字符串、层级、字段数限制；容量/过期轮转显示 dropped，长度/结构截断显示 `truncated=true`。只在本机服务内存保留，不新增磁盘文件或后台上传。退出服务清空；清空按钮只清缓存，继续记录；刷新与正常重连保留当前运行的记录。关闭诊断面板不会停止记录，重启重新开始。已复制的剪贴板文本由用户管理。记录行为与语音采集独立，不会因此开启麦克风或改变任务执行权限。策略见 [ADR 0014](adr/0014-default-voice-and-always-on-diagnostics.md)。

## 如何判断停在哪一步

- 只有“云端读取工具列表”：只证明调用过 tools/list，不能证明会调用开发工具。
- “收到工具调用 → workbench_status → 工具已返回结果”：证明查询了状态，没有创建开发任务。
- “收到工具调用 → workbench_submit → 工具调用被拒绝”：按错误分类核对语音执行许可、项目、上下文窗口、点选和任务状态。
- “已获得 Codex 任务回执”带 task ID：才说明任务入口接受了请求。后续任务状态表示准备、执行、等待确认、完成、失败或停止；具体执行错误看对应任务卡。
- 只有转写/播报，没有工具调用或任务回执：先检查云端工具意图和当前连接配置，不能推断 Codex 执行失败。状态丢失或消息格式不兼容也需要诊断证据排除。

截图或云端角色提示不足以确认根因。复制角色说明位于配置页；它来自同一个 LINGXI_WORKBENCH_ROLE。角色提示是建议，不能保证模型调用工具。控制台配置变更、重新连接和模型替换都需要用户操作/授权，不自动执行。

## 语音聊天记录

用户转写和助手播报显示在右侧，标明“语音”、接收中、最终或中断。重复片段不重复添加；助手说“完成”不构成执行结果。交接状态和 task ID 来自工作台，Codex 结果与语音回复区分。与实际任务相同的用户文字不会在同一任务中重复显示。

这部分正文与脱敏诊断分开：只在本次应用运行的服务内存保留，最多 24 轮、每轮最多 8 条、总计约 64,000 字符；刷新网页或语音重连可以继续查看，退出应用丢失。可在聊天区「清除本次语音记录」。没有新增正文数据库表或云端同步。已提交给 Codex 的任务仍遵循原有任务历史保存规则；清空语音记录不删除未发送草稿、已提交任务或回退文件。

没有项目时也可继续聊天；开发任务仍必须选择项目。消息绑定当时的项目/对话，切换后不自动带入其他项目；项目外的记录放在独立折叠区。首次语音提交创建对话时，只关联本轮的真实回执。旧连接事件被忽略，断连使未完成消息标记中断；已确定内容不因迟到分片重新变成流式。供应商未提供逐句标识时，关联依赖当前收音窗口和有序 WSS，不能假称可以识别所有跨轮迟到消息。

## 最小 Mac 对照

先确认应用运行的是包含诊断补丁的构建；旧安装包不会自动更新。用已有绑定与已授权的麦克风，在测试项目中先用键盘提交“只检查并说明项目入口，不修改文件”。随后口述“请调用工作台工具查询当前项目和任务状态”，再口述“请交给 Codex：只检查并说明项目入口，不修改文件”。每轮结束复制日志，分别检查 status 调用、submit 回执和结果。是否重连或保存控制台角色由用户确认，不新增凭据或绑定。真实七牛链路、Mac 音频和模型能力必须用该对照验收，协议替身通过不能替代。
